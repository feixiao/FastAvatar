 # 端侧 AI 语音助手架构：前台与后台解耦
 
 ## 方案定位
 
 **前台实时交互系统（System 1）与后台认知执行系统（System 2）解耦协作**，核心不是让一个模型同时承担实时听说、复杂推理和工具执行，而是将时延敏感的交互闭环与计算密集的任务处理拆开，再通过显式状态、事件和取消机制协同。
 
 前台负责持续接收语音、判断轮次、提供及时反馈、处理可确定的高频命令，并管理播放与打断。后台负责理解完整请求、规划多步任务、检索记忆、调用工具、校验结果并生成可播报答复。两者通过结构化任务消息与事件流连接；前台不把尚未确认的后台结果说成事实，后台也不能绕过权限和执行策略直接操作系统或车辆。
 
 该方案适用于手机、平板、个人电脑和智能座舱。模型规模、推理设备及端云分工按平台能力配置；分层协作机制保持一致。

 
 ## 一、架构总览
 
 ```text
 麦克风 / 系统音频
       │
       ▼
 声学前端：AEC、降噪、波束成形、声源定位
       │
       ├── 低功耗路径：KWS、VAD、声纹/说话人识别
       │
       ▼
 前台实时交互系统（System 1）
   • 流式语音感知、轮次判断、情绪与韵律线索
   • 高频确定命令的安全路由
   • 及时反馈、流式 TTS、播放状态与打断控制
       │ 任务事件、文本锚点、取消令牌
       ▼
 后台认知执行系统（System 2）
   • 请求理解、上下文组装、工具筛选与任务规划
   • 本地记忆/RAG、受限生成、权限校验
   • 工具执行、结果核验、答复生成
       │ 结果事件 / 进度事件
       └──────────────────────────────► 前台播报与状态更新
 
 端云路由器可作为后台执行能力的一部分：本地优先，必要时按策略请求云端。
 ```
 
 ### 1. 前台实时交互系统（System 1）
 
 前台运行在持续音频路径上，优先满足响应时间、可中断性与资源上限。它可以由流式 ASR 加小型意图模型组成，也可以采用能直接处理音频并输出文本或结构化事件的轻量音频模型。选型不改变接口契约：输入带时间戳的音频帧，输出增量识别、轮次状态、情绪线索和候选意图。
 
 前台的职责：
 
 - 维护音频采集、回声消除参考信号和环形缓冲区；区分用户声音与设备播报。
 - 结合 VAD、韵律和语义完整性判断用户是否说完；识别到用户插话时优先停止播报。
 - 对高频、低风险且参数明确的命令走受限快路径；快路径仍需执行权限、参数范围和设备状态校验。
 - 对需要推理、检索或多步执行的请求立即建立后台任务；可播放简短的接收反馈，但不得提前宣称任务已完成。
 - 将已播放音频对应的文本位置、任务 ID 和轮次 ID 交给会话管理器，支持准确截断与恢复。
 
 前台不是第二个自由执行 Agent。快路径的动作集合应有限、可枚举、可审计；遇到歧义、缺少参数、高风险操作或状态不明时，转交后台或请求澄清。
 
 ### 2. 后台认知执行系统（System 2）
 
 后台处理前台提交的完整或持续更新的请求。它可以运行本地 SLM、云端模型，或两者组合；工具、权限、安全校验和结果验证由确定性服务提供，不依赖模型自行遵守提示词。
 
 典型执行步骤：
 
 1. 根据轮次 ID、已确认文本、可选音频线索及屏幕上下文组装请求上下文。
 2. 从工具目录检索少量相关工具及其参数 Schema，避免把全部 API 定义塞入每次提示。
 3. 生成计划或结构化工具调用；使用 JSON Schema/语法约束解码，并在执行边界再次校验参数。
 4. 检查权限、用户确认要求、设备状态和安全策略；通过受控工具适配层执行。
 5. 对工具返回值做类型与业务状态校验；失败时按明确策略重试、改计划或向用户说明，不得伪造成功。
 6. 产出带有任务 ID、状态、事实依据和播报文本的结果事件，由前台决定何时及如何播报。
 
 后台应支持取消与过期任务隔离。用户打断、撤回请求、开始新轮次或设备状态变化时，旧任务必须收到取消信号；不可取消的外部操作则进入可追踪状态，并在结果返回后按策略处理。
 
 ## 二、协作协议与状态管理
 
 ### 1. 事件契约
 
 前后台通过进程内队列、IPC 或消息总线传递带版本的事件。每个事件至少包含 `session_id`、`turn_id`、`task_id`、单调递增序号和创建时间。音频及文本片段还应携带时间范围；工具请求携带 Schema 版本、权限上下文和幂等键。
 
 建议的事件类型：
 
 | 方向 | 事件 | 含义 |
 | :--- | :--- | :--- |
 | 前台 → 后台 | `TurnStarted` / `TranscriptUpdate` | 新轮次开始及增量识别文本 |
 | 前台 → 后台 | `TaskSubmitted` | 已提交的用户目标、上下文引用及取消令牌 |
 | 前台 → 后台 | `TaskCancelled` | 用户打断、撤回、轮次失效或系统取消 |
 | 后台 → 前台 | `TaskProgress` | 可选的阶段进度，不代表任务完成 |
 | 后台 → 前台 | `ConfirmationRequired` | 展示/播报待确认操作及其摘要 |
 | 后台 → 前台 | `TaskCompleted` / `TaskFailed` | 经工具结果校验后的最终状态与答复 |
 
 消息应引用上下文而不是重复复制大型音频、图像或文档载荷；需要保留的载荷使用有生命周期管理的句柄。跨进程传递时定义超时、背压和队列上限，避免识别速度超过推理速度时无限积压。
 
 ### 2. 任务状态机
 
 ```text
 CREATED → UNDERSTANDING → PLANNING → WAITING_CONFIRMATION
                    │          │                 │
                    │          ▼                 ▼
                    └──────► EXECUTING ─────► VERIFYING → COMPLETED
                                  │                 │
                                  ├──► FAILED ◄────┘
                                  └──► CANCEL_REQUESTED → CANCELLED
 ```
 
 状态转换由任务协调器单点维护，工具执行器不得自行改变会话轮次。终态任务不能覆盖新轮次状态；迟到事件按 `turn_id`、`task_id` 和序号丢弃或归档。需要用户确认的任务只有在确认事件与待确认摘要匹配时才可继续，确认超时则按产品策略取消或保持待处理。
 
 ### 3. 反馈与最终答复
 
 前台可在后台处理期间提供简短反馈，例如“我查一下日程”。该反馈属于交互性语音，不是任务结论。最终答复只能依据已验证的工具结果或模型明确标注的非事实性内容生成。长任务可报告真实进度；工具尚未返回时不得猜测结果。
 
 ## 三、语音轮次、流式处理与打断
 
 ### 1. 从拾音到后台任务
 
 1. 麦克风阵列采集音频；AEC 使用扬声器播放参考信号消除回声，之后执行降噪、波束成形及可选声源定位。
 2. KWS/VAD 在低功耗路径检测唤醒与语音活动；唤醒后将带时间戳的帧送至前台。
 3. 前台持续输出部分识别结果，并结合韵律、语义 EOT 和环境状态更新轮次判断。纯静音阈值只作为特征之一，不能独立决定复杂语句的结束。
 4. 对可确定的安全命令执行快路径；其他请求在合适的语义边界创建后台任务。若识别结果仍在变化，使用增量更新或提交稳定快照，并明确后台允许哪些字段继续更新。
 5. 前台开始反馈或等待后台；后台的最终响应通过文本分块交给 TTS，音频生成与播放采用有界缓冲区。
 
 ### 2. 打断与回滚
 
 TTS 播放期间，AEC 后的输入仍由 VAD 和说话人策略监测。检测到用户插话后，前台按优先顺序：停止音频输出并清空未播放帧；发出当前任务取消信号；记录播放器确认已播放的音频时间戳；将播报文本映射到该时间戳并截断对话历史；创建新轮次。若 TTS 文本与音频无法精确对齐，应记录已确认播放的片段边界，不能把尚未听到的生成文本写入会话历史。
 
 取消与外部副作用分开处理：尚未执行的工具调用应取消；已经提交且无法撤回的操作保留真实执行状态，并在适当时向用户说明。旧任务的迟到结果不得插入新轮次播报。
 
 ### 3. 延迟预算
 
 应按平台和场景实测，而不是把单项模型速度直接当作端到端体验。关键指标包括：唤醒到首个可用识别结果、用户停顿到轮次判定、停顿到首包音频（TTFA）、打断到停止播放、工具完成时延，以及长时间运行的功耗和热稳定性。目标值由产品体验和硬件基线确定；音频流、队列和推理线程都必须有资源上限。
 
 ## 四、工具、记忆与安全边界
 
 ### 1. 工具调用
 
 工具注册表提供名称、用途、参数 Schema、权限级别、可撤销性、幂等语义、超时和结果类型。后台先按当前请求检索候选工具，再生成调用；运行时做 Schema 校验、参数归一化、权限检查和设备状态检查。工具适配层返回结构化结果与错误码，模型只负责理解及表达，不直接获得任意系统调用能力。
 
 涉及付款、删除、对外发送、账户变更或车辆安全的操作，应通过策略表决定是否二次确认。确认内容需准确展示目标与关键参数；用户确认后再次检查状态和权限，避免确认期间上下文已变化。
 
 ### 2. 记忆与上下文
 
 - **会话工作记忆**：保存近期轮次、任务状态、工具结果和实际已播放的助手语音；按容量和保留期限清理。
 - **长期个人记忆**：用户明确授权后，才持久化偏好、实体关系和摘要；支持查看、修改、删除及来源追溯。
 - **本地检索**：SQLite 等结构化存储可承载元数据，向量索引负责语义召回；检索结果作为有来源的上下文，不自动视为真实或最新事实。
 - **屏幕上下文**：仅在操作系统权限允许且用户请求相关任务时读取无障碍树或视觉内容；限制采集范围，并标注时间与来源。
 
 记忆检索、屏幕内容和工具返回值都属于不可信输入。提示注入内容不得改变系统策略、权限或工具白名单。
 
 ### 3. 端侧与云端路由
 
 默认将唤醒、声学前端、轮次状态、权限检查和敏感个人上下文控制留在设备侧。路由器根据联网需求、任务复杂度、设备负载、隐私设置和用户授权选择本地模型或云端模型。发送云端前按策略最小化数据并取得所需授权；网络不可用时，明确区分可本地完成、可排队和无法完成的任务。云端模型与本地模型使用同一工具权限边界，不能因路由变化扩大操作权限。
 
 ## 五、量化与资源预算
 
 前后台解耦的价值之一是可分别预算常驻成本和按需成本。前台小模型、KWS/VAD 与声学处理常驻或低功耗运行；后台 SLM、RAG、视觉编码器及较大的 TTS 组件按任务需要加载或卸载。实际驻留策略应计入操作系统、其他应用、KV Cache、音频缓冲区和峰值并发，而非只统计模型文件大小。
 
 - **前台语音模型**：优先保证流式稳定性、轮次检测和意图分类；按目标 NPU/DSP 采用 INT8 或设备支持的低精度格式。
 - **后台文本 SLM**：按内存带宽与质量需求选择 W4A16、W4A8 或 W8A8；在目标设备上验证算子覆盖、首 token 延迟、工具调用成功率及热稳定性。
 - **KV Cache**：通过 GQA、上下文裁剪和合适的 KV 精度限制峰值内存；保留系统指令、当前目标和工具结果等高价值上下文。
 - **TTS**：量化需以听感、韵律连续性和实时率共同评估；声码器可保留较高精度以避免音质退化。
 - **异构调度**：把常开低功耗检测放在 DSP/AOP/Sensing Hub，把适合固定图的模型放在 NPU，把高带宽自回归解码放在最合适的 NPU/GPU/CPU；避免不必要的数据复制。
 
 量化参数和性能数字依模型、运行时、芯片 SKU、系统负载与温控而变。部署文档应记录校准集、精度格式、分组配置、后端版本、峰值内存和实测结果，不应把单一设备数据推广为全平台保证。
 
 ## 六、平台落地映射
 
 | 平台 | 前台常驻路径 | 后台推理与加速 | 主要约束 |
 | :--- | :--- | :--- | :--- |
 | Apple 芯片设备 | 系统音频栈、低功耗唤醒能力、轻量语音模型 | Core ML/ANE 执行固定图；Metal/MLX 或其他受支持运行时执行文本模型 | 统一内存仍需与应用和系统共享；模型加载、热量及后台任务限制 |
 | 骁龙手机 | Sensing Hub、DSP 与低功耗唤醒路径；主系统唤醒后接手流式交互 | QNN 等设备运行时映射到 Hexagon；按设备支持情况安排 ASR、SLM、TTS | RAM、持续功耗、被动散热、NPU 算子覆盖和应用生命周期 |
 | 骁龙座舱 | Audio DSP 处理多麦、多音区、AEC 和唤醒 | NPU/DSP 运行语音与 SLM；安全域通过受控 IPC 暴露车控服务 | 多音区隔离、实时性、QNX/Android 域边界、车规安全验证 |
 
 平台适配必须落实到运行时可用算子与系统接口，不以芯片理论峰值推断端到端性能。座舱中的安全关键控制由独立安全域或车控服务最终裁决，语音 Agent 只能请求动作。
 
 ## 七、实施顺序与验收
 
 ### 1. 实施顺序
 
 1. 明确会话、轮次、任务和事件契约；实现状态机、取消令牌、超时、背压及迟到结果隔离。
 2. 打通音频采集、AEC/VAD、流式识别、EOT、TTS 播放和基于实际播放时间的打断闭环。
 3. 接入少量低风险工具，建立 Schema 校验、权限策略、幂等处理、结果核验和确认流程。
 4. 引入后台模型、工具检索和记忆；为每一步提供可观测的状态与失败原因，同时控制敏感数据留存。
 5. 增加端云路由及平台专用加速；在目标硬件的真实负载和温控条件下完成性能与可靠性评估。
 
 ### 2. 验收指标
 
 | 指标 | 验收内容 |
 | :--- | :--- |
 | 交互时延 | 分位数统计唤醒、轮次判定、TTFA、工具完成和最终答复时延；注明设备、模型与网络条件 |
 | 打断正确性 | 播放停止时间、已播放文本截断准确性、取消传播以及迟到结果隔离 |
 | 工具可靠性 | 按工具和风险等级统计参数有效率、执行成功率、错误恢复、重复副作用及确认正确性 |
 | 语音质量 | 流式断句、首包时间、实时率、韵律连续性和主观听感 |
 | 资源使用 | 峰值/常驻内存、CPU/NPU/GPU/DSP 占用、能耗、热降频及长时稳定性 |
 | 隐私与安全 | 权限拒绝路径、敏感数据出端策略、记忆删除、提示注入防护和安全域拦截 |
 
 验收阈值需在产品需求与目标设备矩阵中明确，并覆盖噪声、网络断开、并发任务、长时间运行、用户打断及工具失败场景。单一平均延迟或模型离线准确率不足以证明整套架构可交付。
